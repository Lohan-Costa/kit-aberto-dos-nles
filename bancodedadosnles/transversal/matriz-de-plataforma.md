# Matriz de plataforma — Windows ⇄ macOS, variável por variável

> ⭐⭐⭐ **REGRA MASTER DO DESENVOLVIMENTO.** Todo app da família nasce numa plataforma e roda na
> outra — o projeto vive num SSD que troca de máquina. Antes de escrever código que toque em
> **caminho, disco, processo, porta, texto de console ou diálogo do sistema**, consulte a linha
> desta matriz. E ao descobrir algo de plataforma, **registre os DOIS lados na mesma linha** —
> o lado que não foi medido entra como `pendente`, nunca em branco.
>
> **Medido em:** Windows 11 23H2 (10.0.22631) com Media Composer 25.6.0.58781 · macOS 15.6.1
> (24G90, Mac mini M4) com MC 25.12/26.8 instalados · Python 3.12 · SSD exFAT compartilhado.
> Consumível por máquina em [matriz-de-plataforma.json](matriz-de-plataforma.json).

## As 8 regras (o que cada linha abaixo aplica)

1. **Nenhum caminho literal de sistema no código de produto.** Pasta de dados, temp, volumes,
   pasta do NLE: sempre por UMA função que decide por plataforma — e **uma só**; três cópias da
   mesma conta divergem (medido duas vezes, em dois projetos).
2. **Isole testes por variável que os DOIS sistemas leem** (`<APP>_DADOS`), nunca por
   `LOCALAPPDATA`/`HOME` só de um lado. Teste que escreve fora do tmp num SO passa escrevendo na
   pasta real do usuário.
3. **Compare caminho como o DISCO compara, não como a string:** sem maiúsculas e em NFC. E decida
   as regras pela FORMA do caminho (`C:\…` é Windows em qualquer máquina), não pelo SO que roda.
4. **Todo `listdir`/`glob`/`rglob` ignora `._*`, `.DS_Store` e pastas ocultas** — a menos que o
   oculto seja o alvo.
5. **Não confie no PATH herdado.** Processo lançado por atalho, Finder, launchd ou painel recebe
   um PATH mínimo. Procure o binário também onde os instaladores o põem, e diga ONDE procurou.
6. **Subprocesso que morre na partida é ERRO, não fim.** EOF sem a mensagem final = processo morto;
   leia e mostre o stderr.
7. **Cheque se FUNCIONA, não se EXISTE** (venv, modelo, binário, pasta): executar, conferir
   tamanho, conferir versão.
8. **Toda troca de arquivo do usuário preserva o que não são bytes** (atributos estendidos no Mac,
   atributos/ACL no Windows) — `os.replace` e `shutil.copy2` não levam tudo.

## Revisão antes de levar o código para a outra plataforma

Procurar no código (cada padrão é uma linha desta matriz que já custou um defeito):

```bash
rg -n 'LOCALAPPDATA|APPDATA|USERPROFILE|ProgramData|Public\\Documents'   # A, G
rg -n 'os\.name|sys\.platform|platform\.system'                          # todo ramo tem os DOIS lados?
rg -n 'ascii_uppercase|GetLogicalDrives|\{letra\}:|"/Volumes"'               # C: raiz dos discos
rg -n 'shutil\.which|"ffmpeg"|"ffprobe"|"claude"|"python"'               # B: PATH
rg -n 'startfile|xdg-open|powershell|osascript|CREATE_NO_WINDOW'         # B, F
rg -n 'rglob\(|\.glob\(|iterdir\(|listdir\(|os\.walk'                    # C: ._* e ocultos
rg -n 'relpath|is_relative_to|relative_to|\.lower\(\)'                   # C: caixa e NFC
rg -n 'os\.replace|copy2|copyfile'                                       # C: atributos
rg -n 'st_ctime|allow_reuse_address|file:/'                              # C, D, F
rg -n 'setenv\("(LOCALAPPDATA|HOME|APPDATA)'                             # testes isolados só de um lado
```

⭐ **O mesmo, automático:** `python3 bancodedadosnles/verificar_plataforma.py <repo>` lê o
[JSON](matriz-de-plataforma.json), mostra cada ocorrência com os dois lados e a armadilha, e marca
`✓?` onde o conserto parece estar a poucas linhas. `--sem-testes`, `--so-pendentes`, `--resumo`,
`--entrada <id>`, `--json`. É guia, não portão: sai 0 (ou 1 com `--falhar`).

E rodar a suíte **na outra plataforma**, com `PYTHONPYCACHEPREFIX` fora do disco compartilhado,
conferindo depois que nada foi criado na pasta real do usuário.

## Como acrescentar uma linha

1. A variável já tem linha? Complete o lado que falta (ou corrija, com `CORRIGE:` e data).
2. Linha nova: os dois lados, a armadilha em uma frase, a confiança **por lado** quando divergir.
3. A história da descoberta vai para a narrativa da sessão
   ([desenvolvimento-cross-platform.md](desenvolvimento-cross-platform.md) ou o doc do produto);
   aqui fica o fato e o link.
4. Atualizar [matriz-de-plataforma.json](matriz-de-plataforma.json) e, se houver padrão de busca
   novo, a seção de revisão acima.
